# Operator and supervisor quick start

This training uses fictional Northstar Works and synthetic records only. Nothing connects to a production system or sends messages externally.

## Start and orient

Run `python -m scripts.recording` in the project folder and open http://127.0.0.1:8766. Windows users can run `.\Start-Recording.cmd` from PowerShell instead. This creates a new session without changing previous reviews. The scenario clock is fixed at 15 November 2026, 14:00 UTC. It is not a live feed.

Mission Control initially shows 2–15 November. Use period, station and shift controls to define a cohort. All four KPIs, the daily chart and station summaries use that cohort. A dash means no trustworthy measurement, not zero. The evidence coverage bar is not a probability.

**Green** means validated evidence or a clear workflow state. **Amber** means attention/held evidence/past plan, depending on its explicit label. **Blue** means work in progress or an operational investigation. Read the label: color alone does not establish severity or a production failure.

## Alex: inspect and propose

1. Select **Alex · operator** in the bottom-left demo identity selector.
2. Open **Investigate the signal**. The hero incident is INC-1042, order WO-1042.
3. Inspect the timeline: start 06:00, fill finish 06:30, pack start 08:50, completion missing. The 140-minute wait is visible even though the final duration is uncertain.
4. Expand **Examine BUF-1042 · edge-buffer receipt**. Compare order, count (720 each), event identity E-WO-1042-4, completion 09:10 and receipt 09:12.
5. Choose **Human review**. Write a note of at least ten characters and **Acknowledge & take ownership**.
6. Write the verified evidence and **Propose receipt recovery**. The proposal is pending; no KPI change is made yet.

Do not claim that a transfer failure or material shortage is established. Receipt agreement supports an analytics correction; event timing alone does not explain the long wait.

## Sam: independently review

1. Switch to **Sam · supervisor**, examine the evidence and pending proposal.
2. Record an independent review note and **Approve recovery**. Rejection is also available and leaves the order held; Alex can then submit a new proposal.
3. Confirm the reporting impact: 720 units, 190 minutes elapsed, still late. Approval is blocked if any other validation finding remains.
4. Add a disposition note (40+ characters and six distinct words) and **Resolve data incident**. INC-1043 remains a separate operational investigation.
5. Open **Audit trail** to inspect actors, times, before/after states and the receipt reference.

Supervisor self-approval is prohibited. These selectable identities are a role demonstration, not actual authentication. There is no product release.

## Explore and hand over

- **Order Explorer:** search a work-order ID, SKU, product name or station; select an evidence state; paginate; open the record. Inspect raw values and recorded quality checks.
- **Shift handover:** on Mission Control, shows all unresolved operational incidents first, then all data incidents ranked by planned volume. The full held-order register is expandable. Scope and outside-scope counts are explicit. Existing review notes and structured next steps remain distinct from verified completed work. It is not generated by an LLM.
- **Export trusted data:** downloads all trusted orders in the selected period/station/shift. Search and pagination do not narrow it.
- **Data Trust:** shows all-source rules and held evidence, regardless of overview filters. Admin Robin can export and reimport raw JSON to demonstrate idempotence, then run validation. Only BUF-1042 has an implemented review-recovery path in this slice; the other seeded defects remain held.
- **Method Lab:** compares rules and robust statistical scoring on trusted data, then challenges the result with six additional conditions. Expand sensitivity and false-alert/miss examples. Precision/recall use planted labels, not real production outcomes.
- **Field Guide:** record feedback, inspect its register and browse the metric dictionary. For a fresh rehearsal, run `.\Start-Recording.cmd` and open port 8766. The original database is preserved; there is no reset button.

## Hand over the operational question

Open INC-1043 → Human review. If open, Sam can acknowledge it to take ownership. Inspect the observed fill-to-pack interval and the existing review note. Record a **Next investigation step**, **Missing information**, and select the relevant source rows. Each statement needs at least 30 characters and six distinct words. Select R-WO-1042-2 and R-WO-1042-3 when discussing that interval. Click **Record next step**, then inspect Mission Control → Shift handover. The note is an intention; do not describe it as a completed log review.

Leave INC-1043 open for the guided recording. If an operational case really needs a recorded disposition in a disposable rehearsal, expand **Close operational investigation**. Sam must select administrative closure or mitigation, document rationale and uncertainty, select evidence, and explicitly confirm. Mitigation additionally needs an action-and-verification statement. Cause remains unestablished. Reopening retains evidence, the prior closure and its uncertainty. A supervisor's free text is not independently verified by this demo.

## Troubleshooting

| Symptom | Action |
|---|---|
| `python` not recognized | Use `Start-Recording.cmd` on Windows. Python 3.11+ must be installed; the launcher searches common installation locations and PATH. |
| Page cannot connect | Keep the server terminal open; check the printed port. Try `--port 8767` if 8766 is occupied. |
| Write says same-origin/token required after server restart | Reload the browser to obtain the new per-server token. |
| Disabled action | Check role, incident state and findings. Admin is intentionally not an approver. |
| “Incident changed” | Reload, inspect the new revision and re-enter a fresh review note. Nothing was overwritten. |
| Batch row collision | Same `row_id` has different evidence. Import was rejected atomically; use original source IDs, not silent replacement. |
| Imported record has no matching order | Inspect unmatched raw evidence in Data Trust. It remains excluded from production KPIs. |
| Sampled check fails | It is an observation, not an automated quarantine/release of product. No product-release function exists. |
| Metrics rise after recovery | An excluded late order re-entered reporting. This is expected; compare denominators and the receipt. |

Stop the server with Ctrl+C. Reviews persist across ordinary restarts in SQLite.

## Small glossary

**Staging:** retaining source evidence before trusting it for analytics. **Quarantine/held:** excluding an entire affected order from KPIs while retaining its source. **Incomplete:** an open order whose route is not finished. **Receipt:** separately retained evidence proposed for recovery. **MAD:** median absolute deviation, a robust measure of spread. **Hypothesis:** a possible explanation that needs further evidence. **Revision:** a number used to reject stale writes. **Audit:** who changed what, when and with which evidence.
